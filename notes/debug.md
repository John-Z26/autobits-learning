# Debug 记录
> 记录 7 类常见错误的排查过程，每条按「现象 / 复现 / 假设 / 证据 / 根因 / 修复 / 验证」组织。其中第 6 条是「验证型」——
> 主动测试异常输入、确认防御有效，修复栏写“不需要修复”是结论，不是遗漏。

## 1. 换到其他目录运行时报 FileNotFoundError

**现象：**
从 C:\Users\ASUS 目录执行 C:\Student_statistics\.venv\Scripts\python.exe src\run.py，
报 FileNotFoundError: [Errno 2] No such file or directory: 'data/students.json'

**复现：**
1. 项目根目录下 python src/run.py → 正常运行
2. cd 到上一级，用绝对路径调同一个脚本 → 报错

**假设：**
第一反应是"data/students.json 没提交"。

**证据：**
- 在项目根目录 ls data/ → students.json 在，文件没丢
- 在 C:\Users\ASUS 下 ls data/ → 没有这个目录
- git status → 工作区干净，文件已提交

三条证据把"文件丢失"排除了。

**根因：**
`open('data/students.json')` 用的是相对路径，相对的是**当前工作目录**，
不是脚本文件所在目录。所以在别的目录运行时，程序会去那个目录下找 data/。

**修复：**
不改代码。README 中已声明"必须在项目根目录运行"。
（彻底的做法是用 `os.path.dirname(__file__)` 拼绝对路径，但这会牺牲"直接跑"的便利。）

**验证：**
回项目根目录执行 python src/run.py，正常加载 2 条记录。

## 2. JSON 缺少外层方括号导致 Extra data

**现象:**
数据文件里并排写了两条学生记录、但外面没有 `[]`：

```json
{
  "id": "2026001", "name": "Alice", "score": 92
},
{
  "id": "2026002", "name": "Bob", "score": 76
}
```

运行时程序没有崩溃，而是打印：
错误:JSON 格式错误，第 6 行第 2 列：Extra data

**复现：**
把 data/students.json 的内容改成上面这样（去掉最外层的 `[` 和 `]`），
在项目根目录执行 python src/run.py。

**假设：**
第一反应是"程序应该会跳过出错的那条记录，继续加载剩下的"。
因为我在校验逻辑里写了"非法记录自动跳过并给警告"，
以为 JSON 解析层也是同样的按条容错。

**证据：**
- 提示只有一行，没有任何"学生信息加载完成，共 N 条"的输出 → 说明**一条都没加载**
- 把文件改回带 `[]` 的格式，立刻正常加载 2 条
- 报错位置是"第 6 行第 2 列"，不是第 1 行 → 说明解析器已经读完了第一段，是在**后面**才出问题

**根因：**
JSON 规范要求**一个文件顶层只能有一个值**。
解析器读到第一个 `{...}` 结束时，认为"文档到此为止"，
后面的 `,{...}` 就成了预期之外的多余数据 → Extra data。

这和我的假设正好相反：**JSON 解析是全有或全无的**——
任何一处不合法，整份文件都拿不到结果，不存在"跳过坏的那条"。
"跳过坏记录"那套逻辑，是我在拿到 list 之后逐条校验时才生效的。

**修复：**
在文件最外层加上 `[` 和 `]`，让顶层成为一个数组：
```json
[
  { "id": "2026001", "name": "Alice", "score": 92 },
  { "id": "2026002", "name": "Bob", "score": 76 }
]
```

**验证：**
重新运行，输出「学生信息加载完成，共 2 条有效记录」，两条都能查到。

## 3. 合并 dev 到 main 时 README.md 冲突

**现象：**
git merge dev 后提示：
CONFLICT (content): Merge conflict in README.md
Automatic merge failed; fix conflicts and then commit the result.

**复现：**
main 和 dev 都修改了 README.md 的标题行

**假设：**
以为 Git 会自动选一个版本（取新的或者取 main 的）

**证据：**
打开 README.md 看到 <<<<<<< HEAD / ======= / >>>>>>> dev 三段标记

**根因：**
两个分支改了同一文件的同一区域，Git 无法判断该保留哪个，就把决定权交给人

**修复：**
1. 手动删除 <<<<<<< ======= >>>>>>> 三行标记
2. 保留想要的内容（当时保留的是 main 的标题）
3. git add README.md → git commit

**验证：**
git log --graph 看到分叉和合并点；文件内容正确

## 4. 访问不存在的路径返回 404

**现象：**
请求 `https://www.baidu.com/this-page-does-not-exist`，返回：

```
HTTP/1.1 404 Not Found
Content-Type: text/html
...
```

**复现：**
```bash
curl.exe -i https://www.baidu.com/this-page-does-not-exist
```
（PowerShell 里必须写 `curl.exe`，直接写 `curl` 会走 Invoke-WebRequest 别名，参数不认）

**假设：**
我以为会"连不上"或者超时。
因为地址是随手编的，直觉上"没有这个东西"应该等于"根本访问不到"。

**证据：**
- 访问真实路径 `https://www.baidu.com/` → `HTTP/1.1 200 OK`
- 访问假路径 → `HTTP/1.1 404 Not Found`
- **两次都拿到了完整的响应头** —— 说明 DNS 解析成功、TCP 连接建立、TLS 握手完成、服务器正常回了话

**根因：**
404 不是"连不上"，是"**服务器连上了，但你要的东西它没有**"。

请求完整走完了整条链路：
```
DNS 解析 → TCP 连接 → TLS 握手 → 发 HTTP 请求 → 服务器处理 → 回 404
```
每一环都成功，只是最后一步服务器查了路由表，发现没有这个路径，
于是按 HTTP 协议回了一个 404 状态码。

**修复：**
不用修复，这是服务端的正常响应。

区分两种"打不开"：

| 现象 | 含义 | 哪一环断了 |
|---|---|---|
| **404** | 服务器在，资源不在 | 最后一环（服务器处理） |
| **连接失败** / 超时 | 连服务器都没连上 | 前面某一环（DNS / TCP / 端口） |

**验证：**
同一台服务器，真实路径 200、假路径 404 ——
差别在"资源是否存在"，不在"网络是否通"。

## 5. 端口被占用导致绑定失败

**现象：**
第二个程序尝试绑定 `127.0.0.1:9999` 时，报：

```
OSError: [WinError 10048] 通常每个套接字地址(协议/网络地址/端口)只允许使用一次。
```

**复现：**
- 终端 A：用 socket 绑定 9999 并 listen，然后 sleep 保持不退出
- 终端 B：再绑同一个端口

**假设：**
我以为"换个程序就能重新用这个端口"。
当时没意识到端口是**整台电脑共享的资源**，不是某个程序私有的 ——
就像门牌号，一家占着，另一家就不能用同一个号。

**证据：**
- 终端 A 打印「已占用」，说明第一个程序确实占住了
- `netstat -ano | findstr :9999` 输出：
  ```
  TCP  127.0.0.1:9999  0.0.0.0:0  LISTENING  28364
  ```
  `LISTENING` = 正在监听，`28364` = 占用它的进程 PID
- **反差**：用 `python -m http.server 8000` 开两个窗口，两个都不报错

**根因：**
TCP 端口是操作系统级别的独占资源，同一时刻只能被**一个进程**绑定监听。
第二个进程来绑，系统发现这个"门牌号"已经有人，直接拒绝。

但 `http.server` 是个例外：它内部设了 `SO_REUSEADDR` 选项，
而 **Windows 对这个选项的处理比 Linux 宽松** —— 允许两个 socket 绑同一端口
（实际只有一个能收到连接）。所以那种写法造不出这个错误。

**修复：**
两种办法：
1. 换一个没被占用的端口（比如 9999 → 9998）
2. 杀掉占用它的进程：`taskkill /PID 28364 /F`

**验证：**
- 杀掉 28364 后重新绑 9999 → 成功
- `netstat -ano | findstr :9999` 里不再有 LISTENING 记录

## 6. 程序输入为空或非法时的处理验证

**现象：**
在菜单提示后直接回车，程序显示「输入错误，请重新输入」并重新回到菜单，
没有崩溃也没有报错。输入纯空格、输入字母 `abc`，行为完全一致。

**复现：**
运行 `python src/run.py`，在「请输入您的操作(1-7):」后直接按回车；
再分别试输入三个空格、输入 `abc`。

**假设：**
担心会崩。`input()` 拿到的永远是字符串，空串和字母都不在 "1"~"7" 里，
如果直接拿去比较或转成数字，可能无匹配，也可能抛 `ValueError`。

**证据：**
- 三种输入都只输出同一句提示，没有 traceback，程序也没退出
- 代码里是 `choice = input(...).strip()` —— 先把首尾空白清掉再进 `match`
- `match` 末尾有 `case _:` 兜底，所有不在 1~7 的值都走这一支
- 空串、纯空格 `strip` 后都是 `""`，`"abc"` 也不匹配任何 case，三者最终都落到 `case _`

**根因：**
防线有两道：`.strip()` 消除「看起来输了、其实全是空白」的情况，
`case _` 兜住所有非法值，提示后重新循环。

因为输入进入 `match` 之前已经规范化过，所以不会出现匹配不上就跑飞的情况。

**修复：**
**不需要修复，这已经是正确行为。**

这条记录的作用不是发现缺陷，而是确认防御真的有效 ——
留下证据说明三种典型异常输入都被拦住了，而不是只靠"我记得加了处理"。

**验证：**
三种异常输入各跑一次，行为完全一致；
正常输入 1~7 仍能进入对应功能，没有误伤。

## 7. 成绩填成文字导致 ValueError

**现象:**
数据文件里有一条 {"id": "2", "name": "B", "score": "abc"}，
运行时没有崩溃，但这条记录没有被加载，输出「学号 2 的成绩不是数字，已跳过」。

**复现:**
把 data/students.json 里的 score 改成字符串 "abc"，运行 python src/run.py。

**假设:**
一开始以为是我的校验逻辑写错了 —— 明明写了"跳过非法记录"，
为什么还要报错？怀疑 try 的位置放错了。

**证据:**
- 单独跑 float("abc")，报 ValueError: could not convert string to float: 'abc'
- 报错位置在 score = float(score) 这一行，不在 open() 那一行
- 说明文件读取正常，问题出在类型转换

**根因:**
float() 只能把"看起来像数字的字符串"转成浮点数。
"abc" 不满足，抛 ValueError。JSON 允许字符串，所以文件本身是完全合法的。

**修复:**
在转换那一步外面包 try/except (TypeError, ValueError)，
捕获后打印警告、跳过这条记录，不影响其余数据。

**验证:**
用 README 里的验证数据跑，输出 3 条警告 + 「共 1 条有效记录」，与 README 描述一致。

## 8. 列表越界导致 IndexError

**现象：**
执行 `[1, 2, 3][10]`，报：

```
IndexError: list index out of range
```

**复现：**
```python
lst = [1, 2, 3]
lst[10]
```

**假设：**
我以为越界会返回 `None` 或者 `[]`，像很多语言那样"读不到就算了"。

**证据：**
- `lst[10]` → `IndexError`
- `lst[10:20]` → 返回 `[]`，**不报错**
- `lst[-1]` → 返回 `3`（负数索引从末尾数）

同一个列表，三种取法，三种行为。

**根因：**
- **索引访问** `[i]` 要求位置 i 必须存在，不存在就是编程错误，直接抛异常
- **切片访问** `[a:b]` 的语义是"取范围内的元素"，范围可能为空，所以返回空列表而不报错
- **负数索引** 是从末尾倒数，`-1` 是最后一个

**修复：**
取固定位置前先判断长度：
```python
if len(lst) > i:
    value = lst[i]
```
或者用切片 / `for` 遍历，天然不会越界。

**验证：**
```python
lst = [1, 2, 3]
lst[10]        # IndexError
lst[10:20]     # []
lst[-1]        # 3
```
