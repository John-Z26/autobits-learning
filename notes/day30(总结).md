一个命令行学生成绩统计工具，184 行，只用了 Python 标准库。我花时间最多的是异常处理：

数据层面的 8 类问题我都试过，程序没有崩，会给提示，不是直接抛一屏报错 —— 空文件、JSON 格式错、字段缺失、类型错误、成绩超范围、学号重复、文件权限不足、编码错误。

README 里写了可复现的验收步骤，用一组异常数据跑，能出 3 条警告 + 1 条有效记录。

**工程习惯**

notes/debug.md 8 条，每条按「现象 / 复现 / 收集信息 / 提出假设 / 验证 / 修复 / 再次验证」写，覆盖培养方案列的 7 类错误中的 6 类。环境变量那一类还没做，因为项目里暂时用不上。

## 三、还差什么

**1. 2.4 数据结构：主动跳过**

9 个小节里 7 个我本来就有概念，34 道题里 list / dict / set 天天在用。剩下的实测性能对比，我先跳过了。

**2. 2.8 的 .env：延后**

我的项目没有密钥、只有一个环境、只有我一个用户，四个判断条件一个都不满足。硬加上去只是照抄，被问「为什么要用」会答不上来。

正确做法我知道：配置和代码分开、密钥进 .env 并被 gitignore 挡掉、给别人一份 .env.example。等真正接数据库时再落地。

**3. 算法停在递归**

27 题都在模拟、排序、字符串、递推这个层面，回溯和动态规划一次没碰过。

原计划最后一道是 P1706 全排列，我做到一半发现自己连递归都没独立写过，就换成了 P5739 阶乘。这个判断我觉得是对的，但确实暴露出基础缺口。

## 五、待咨询老师的问题

下面四个问题是我安排下一阶段时一直想不明白的：

**背景**：我暑假自学过 C++，学到数组就停了，没继续。现在 27 道算法题全部用 Python 写的。听说算法竞赛用 C++ 更占优势（性能、STL），但也感觉 Python 的算法学习资源比 C++ 少一些。

**想问**：接下来算法这条线，是继续用 Python，还是回头把 C++ 补起来？如果两个都要，建议的先后顺序是什么？

**我现在是这么想的**：想先把 Python 学下去，因为 27 题的经验都在 Python 上，换语言等于从零重来。但不确定长期看这个判断对不对。
