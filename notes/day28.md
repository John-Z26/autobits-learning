# 2026-11-16 基础安全意识（2.10）

## 2.10.1 密码与 Token
敏感信息 8 类：密码 / API Token / Access Key / Secret Key / 私钥 / 数据库密码 / Cookie / Session

五个不要：公开群 / 公开仓库 / 截图 / 公开文档 / 发给第三方 AI

★ Cookie 也算 —— 泄露等于别人能以你的身份登录

## 2.10.2 私钥
私钥（`id_rsa`）绝不分享；能给别人的是公钥（`.pub`）。

## 2.10.3 最小权限
只给完成当前工作所需的最低权限，不为了方便给管理员。

## 2.10.4 sudo
报权限错误别反射性加 `sudo`。先问：为什么需要？谁该拥有这文件？程序真需要管理员吗？

★ 典型滥用：`sudo pip install` —— 这就是要用 venv 的原因

## 2.10.5 危险操作
删除 / 覆盖 / 格式化 / 改数据库 / 生产部署 / 改权限
前问四句：目标？影响范围？能否恢复？有没有备份？

## 2.10.6 生产环境
无授权不：删数据 / 改权限 / 重启关键服务 / 执行未知脚本。

★ 生产出错的代价是真实用户受影响，不是"重跑一次"

## 2.10.7 外部代码
不直接执行网上抄的命令。先搞清：下载什么？改哪里？要什么权限？

★ `curl xxx | bash` 最危险 —— 内容看都不看就执行

## 2.10.8 AI 工具安全
发前检查：Token / 密码 / 用户数据 / 服务器地址 / 内部配置

★ 发出去 = 上传到别人的服务器

## 阶段练习：9 项判断

| 内容 | 提交 | 理由 |
|---|---|---|
| README.md | ✅ | 项目说明 |
| .env | ❌ | 真实配置值 |
| .env.example | ✅ | 只有键名 |
| 数据库密码 | ❌ | 凭据 |
| SSH 公钥 | ✅ | 本来就公开 |
| SSH 私钥 | ❌ | 身份证明 |
| 普通源代码 | ✅ | 项目本身公开 |
| 真实用户数据 | ❌ | 隐私 |
| 测试用假数据 | ✅ | 但需确认真是假的 |

**分界线：这个值拿到能不能直接用？能 → ❌，不能 → ✅**
